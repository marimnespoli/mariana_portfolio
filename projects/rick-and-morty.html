The Goal

Build a character explorer that talks to a real public API — no mock data, no shortcuts. Users needed to search and filter Rick and Morty characters in real time, with multiple filters working simultaneously.

The constraint: no frameworks. Just TypeScript, the native Fetch API, and CSS. Every abstraction had to be hand-rolled.

02

The Approach

A single filter-state object owns all active filters. On every change, it serialises itself into a URL query string and fires one typed fetch() call. The UI updates from the resolved JSON — no duplication, no stale state.

TypeScript interfaces enforce the API contract at compile time, so runtime surprises are caught before the browser ever sees them.

Technical Highlights

Filter State

state

One object owns all active filters. Every input change updates it and immediately triggers a URL rebuild and fetch — no duplicate logic anywhere.

const filters: FilterState = {
  name: "",
  status: "",
  species: "",
  gender: "",
};

function updateFilter(
  key: keyof FilterState,
  value: string
) {
  filters[key] = value;
  fetchCharacters(filters);
}

API Fetching

fetch

Typed async/await fetch with dynamic query params. URLSearchParams strips empty strings automatically so the API never receives blank filters.

async function fetchCharacters(
  f: FilterState
): Promise<Character[]> {
  const params = new URLSearchParams(
    Object.fromEntries(
      Object.entries(f).filter(([, v]) => v)
    )
  );
  const res = await fetch(
    `${BASE_URL}?${params}`
  );
  const data = await res.json();
  return data.results ?? [];
}

TypeScript Types

types

Interfaces derived from the Rick and Morty API schema. If the API shape changes, TypeScript surfaces every broken access immediately at compile time.

interface Character {
  id: number;
  name: string;
  status: "Alive" | "Dead" | "unknown";
  species: string;
  gender: string;
  image: string;
  location: { name: string };
}

interface FilterState {
  name: string;
  status: string;
  species: string;
  gender: string;
}

Card Rendering

dom

Characters render as template-literal HTML injected via innerHTML. Status colour is set inline — no external library needed for the conditional logic.

function renderCard(c: Character) {
  const colour =
    c.status === "Alive" ? "#4caf50"
    : c.status === "Dead" ? "#e84c4c"
    : "#aaa";
  return `
    <div class="card">
      <img src="${c.image}" alt="${c.name}">
      <h3>${c.name}</h3>
      <span class="dot"
        style="background:${colour}">
      </span>
      ${c.status} — ${c.species}
    </div>`;
}
